## 강조할 것

1. **서브쿼리가 돌려주는 모양**(값 / 목록 / 표)을 먼저 말하게 하세요. 모양이 어디에 쓸 수 있는지를 결정합니다.
2. **NOT IN은 습관적으로 NOT EXISTS로.** 실무에서 "데이터가 하나도 안 나와요"의 대표 원인입니다.
3. **CTE = 단계별 작업.** "① 재료 → ② 묶기 → ③ 비교"로 이름 붙여 쓰는 습관은 Ch07 이후와 실무 리포트 쿼리 전체에 이어집니다.
4. **동점 처리는 요청자에게 묻는다.** RANK냐 ROW_NUMBER냐는 SQL 문제가 아니라 비즈니스 결정입니다.

## 자주 나오는 질문

| 질문 | 답변 요지 |
|---|---|
| "서브쿼리랑 JOIN 중 뭐가 빨라요?" | MySQL 8 옵티마이저가 상당 부분 같은 실행 계획으로 바꿈. 먼저 읽기 쉬운 쪽으로, 느리면 EXPLAIN(Ch10) |
| "CTE랑 뷰(VIEW) 차이는?" | CTE는 그 쿼리 안에서만, 뷰는 DB에 저장되어 계속 재사용(Ch10) |
| "`ANY`, `ALL`은요?" | `> ALL (목록)` = 목록의 최댓값보다 큼, `> ANY` = 최솟값보다 큼. 정보처리기사에 나옴. MAX/MIN 서브쿼리로 쓰는 게 읽기 쉬움 |
| "전월 대비 증감은 어떻게 해요?" | `LAG(값) OVER (ORDER BY 월)` — 이전 행 값을 가져오는 윈도우 함수. 심화 과제로 |
| "WITH RECURSIVE는?" | 계층·연속 날짜 생성용. 입문 범위 밖 |
