## 강조할 것

1. **DELIMITER는 Workbench에게 하는 말이다.** 서버는 `DELIMITER`를 모릅니다. 그래서 `DELIMITER $$` 줄에 `;`를 붙이면 안 되고, 마지막에 `DELIMITER ;`로 되돌리지 않으면 다음 쿼리가 실행되지 않습니다.
2. **막을 거면 BEFORE, 기록할 거면 AFTER.**
3. **트리거는 같은 트랜잭션.** 6-1절 화면(트랜잭션 안에서는 이력 6행 → ROLLBACK 후 5행)을 꼭 보여 주세요.
4. **트리거의 에러는 문장을 실패시킬 뿐, 트랜잭션은 여는 쪽이 정리한다.** Ch08의 "에러 ≠ 자동 ROLLBACK"이 다시 나옵니다. Ch12 프로시저의 `EXIT HANDLER … ROLLBACK`으로 이어지는 복선입니다.
5. **트리거는 문서화.** 실습 10번 결과표를 README에 붙이는 습관.

## 수업 운영 팁

- **가장 흔한 막힘 ①**: `DELIMITER ;`로 되돌리지 않음 → 이후 `SELECT …;`가 실행되지 않고 다음 `$$`까지 기다림. Workbench 탭을 닫았다 열면 기본값(`;`)으로 돌아옵니다.
- **가장 흔한 막힘 ②**: 트리거를 고치려고 같은 이름으로 다시 `CREATE` → 1359 Trigger already exists. 수정 명령이 없으므로 `DROP TRIGGER IF EXISTS` 후 다시 생성. 실습 중에는 트리거 위에 `DROP TRIGGER IF EXISTS 이름;`을 붙여 두게 하면 편합니다.
- **가장 흔한 막힘 ③**: `DECLARE`를 `IF` 뒤에 씀 → 1064. `DECLARE`는 `BEGIN` 바로 뒤에 모아서.
- Workbench 왼쪽 Navigator에서 테이블 → **Triggers** 폴더를 열면 만든 트리거가 보입니다. 테이블 우클릭 → Alter Table → **Triggers** 탭에서 GUI로 편집할 수도 있다고 알려 주세요(내부적으로는 DROP + CREATE).
- 실습 7번은 트리거 연쇄(orders → customer_coupons의 BEFORE 트리거)가 생깁니다. 시간이 되면 화이트보드에 화살표로 그려 주세요.
- `changed_at`이 실행한 날짜(오늘)로 찍히는 것에 학생들이 놀랄 수 있습니다. 교안 데이터의 "오늘"(2026-06-30)은 가상의 기준일이라고 짚어 주세요.

## 자주 나오는 질문

| 질문 | 답변 요지 |
|---|---|
| "문장 단위(FOR EACH STATEMENT) 트리거는요?" | MySQL은 행 단위만. PostgreSQL·Oracle은 둘 다 지원 |
| "TRUNCATE에도 DELETE 트리거가 도나요?" | 안 돎. TRUNCATE는 DDL이라 행 단위 삭제가 아님 |
| "FK의 ON DELETE CASCADE로 지워진 행도 트리거가 돌아요?" | MySQL(InnoDB)에서는 **안 돎**. 주의할 함정 |
| "트리거 때문에 느려지나요?" | 행마다 실행되므로 대량 UPDATE에서는 체감됨. 본문은 짧게 |
| "트리거와 프로시저 차이는?" | 트리거는 이벤트에 자동 실행, 프로시저는 `CALL`로 직접 실행 (Ch12) |

## 자주 하는 실수

| 실수 | 증상 | 대처 |
|---|---|---|
| `DELIMITER ;` 빠뜨림 | 다음 쿼리가 실행 안 됨 | `DELIMITER ;` 실행 또는 탭 새로 열기 |
| AFTER 트리거에서 `SET NEW` | 1362 | BEFORE로 |
| 같은 이름 다시 CREATE | 1359 | `DROP TRIGGER IF EXISTS` 먼저 |
| 트리거가 걸린 테이블을 본문에서 UPDATE | 1442 | 같은 행은 BEFORE에서 `SET NEW.열` |
| 트리거 안 `COMMIT` | 1422 | 트랜잭션은 바깥에서 |
| `IF OLD.x <> NEW.x` 조건 없이 이력 기록 | 아무것도 안 바뀌어도 이력 생김 | 실제로 바뀐 경우만 |
| NULL 비교를 `<>`로 | NULL → 값 변경을 못 잡음 | `NOT (OLD.x <=> NEW.x)` (NULL 안전 비교) |
