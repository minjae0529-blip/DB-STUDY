## 강조할 것

1. **먼저 SELECT.** UPDATE·DELETE 전에 같은 WHERE로 SELECT → 행 수 확인 → 실행 → `row(s) affected`가 같은지 대조.
2. **안전 업데이트 모드는 끄지 않는다.** 인터넷에 "1175 해결법 = 안전 모드 끄기"가 많이 나옵니다. 끄는 대신 키 조건으로 범위를 좁히는 게 정답이라고 분명히 말해 주세요. `IN (서브쿼리)`는 키 조건으로 인정되지 않는다는 점(실습 6번)도 짚어 주세요.
3. **에러가 나도 자동 ROLLBACK이 아니다.** 6-3절은 많은 학생이 놀라는 장면입니다. 백엔드 과정의 `@Transactional`이 왜 필요한지로 연결하세요.
4. **"영향받은 행 수"로 판단한다.** 0행 UPDATE는 에러가 아니지만 업무적으로는 실패입니다(6-2절, 실습 10번).

## 수업 운영 팁

- Workbench 툴바의 **자동 커밋 토글**(Toggle auto-commit mode)을 끄면 모든 문장이 트랜잭션 안에서 실행됩니다. 오늘은 **켠 상태**(기본값)에서 `START TRANSACTION`으로 명시하는 방식을 씁니다. 학생 PC 설정이 제각각이면 결과가 달라지니 수업 시작 때 확인하세요.
- 트랜잭션을 열어 둔 채 다른 탭에서 같은 행을 바꾸면 잠금 대기(1205)가 납니다. 실습 중 "멈췄어요"의 대부분은 **다른 탭에 열린 트랜잭션**입니다. 해당 탭에서 COMMIT 또는 ROLLBACK하면 풀립니다.
- 실습 중 데이터가 꼬이면 setup.sql의 DROP 줄 주석을 풀고 다시 실행하면 됩니다. 이 챕터에서 챕터별 DB 방식의 장점이 가장 크게 드러납니다.

## 자주 나오는 질문

| 질문 | 답변 요지 |
|---|---|
| "COMMIT 안 하고 Workbench를 끄면요?" | 접속이 끊기면 열린 트랜잭션은 ROLLBACK됨 |
| "`REPLACE INTO`, `INSERT … ON DUPLICATE KEY UPDATE`는요?" | 있으면 수정, 없으면 삽입(upsert). MySQL 전용. 심화 |
| "TRUNCATE는 ROLLBACK 안 돼요?" | DDL이라 암묵적 커밋. 되돌릴 수 없음 |
| "트랜잭션을 길게 열어 두면 안 돼요?" | 잠금을 오래 쥐어 다른 사용자가 기다림. 짧게 열고 빨리 닫기 |
| "UPDATE에 JOIN을 쓸 수 있어요?" | MySQL은 됨(실습 6번). 표준 SQL·다른 DBMS는 문법이 다름 |

## 자주 하는 실수

| 실수 | 증상 | 대처 |
|---|---|---|
| WHERE 없는 UPDATE/DELETE | 1175 (안전 모드) / 전체 변경 | 키 조건 + 먼저 SELECT |
| 열 목록 없는 INSERT | 1136 Column count doesn't match | 열 목록 명시 |
| `MAX(order_id)`로 새 번호 | 동시 주문 시 남의 번호 | `LAST_INSERT_ID()` |
| 같은 테이블을 서브쿼리로 읽으며 UPDATE/DELETE | 1093 | FROM절 서브쿼리로 한 번 감싸기 / JOIN |
| 트랜잭션 연 채로 다른 탭 작업 | 1205 Lock wait timeout | 열린 탭에서 COMMIT/ROLLBACK |
| 에러 후 그대로 COMMIT | 반쪽 데이터 저장 | 에러 나면 ROLLBACK |
